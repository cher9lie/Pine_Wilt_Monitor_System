1.3	用户权限等级
在权限等级方面，本系统构建以“业务安全”为核心的职能权限矩阵。通过“权责对等、数据脱敏、交叉制约”三大原则，确保系统高效协同、严守数据底线。
本系统将用户划分为五个核心域：
（1）	管控域通过‘审管分离’确保底座安全；
（2）	技术域严格管控数据流向，确保数据主权；
（3）	管理域引入了‘复核’与‘自动核算’，防范管理漏洞；
（4）	决策域强调决策过程的透明与存档；
（5）	访问域则利用时空脱敏技术，在保护疫区隐私的前提下，赋能科研与社会监督。

	数据库管理员	数据库更新维护、表结构管理、数据备份恢复、数据安全管理

1.4	详细用户需求
1.4.1	直接业务人员用户需求
1.4.1.1	遥感工程师
功能模块名称：多源遥感数据管理模块、智能模型训练模块、疑似病害识别模块、监测成果校正模块
需求描述：遥感工程师负责对卫星遥感影像、无人机影像及历史样本资料进行整理和判读，需要平台支持多源影像统一管理、疑似病害区域提取、样本数据积累和识别结果校正。该类用户的主要需求是提高大范围松林病害筛查效率，为森防站研判和林场核查提供初步线索。
业务规则：遥感影像应按监测区域、采集时间、数据来源和处理状态进行归类；疑似病害区域应与行政区、林班小班或重点监测区保持空间对应；智能识别结果不能直接作为最终灾害结论，应经过人工复核或地面核查确认；经现场核查确认的样本应回流至样本库，用于后续模型训练和识别结果修正。
功能指标：支持多源影像资料的统一登记与查询；支持疑似病害区域、疑似疫木点位和样本记录的关联管理；支持智能模型训练批次、识别结果和校正结果的记录；支持输出疑似病害分布图、监测成果说明和重点核查区域清单。
预期结果：形成较稳定的遥感监测工作流程，减少重复判读和资料分散问题；提高疑似病害区域发现效率；为地面核查、灾害研判和分级预警提供可靠的前端监测成果。
1.4.1.2	林场管理人员
功能模块名称：巡查任务管理模块、防控处置管理模块、资源调度模块、处置进度跟踪模块
需求描述：林场管理人员负责辖区内巡查、核查和防控处置工作的组织协调，需要平台把上级预警信息和疑似病害点位转化为具体工作任务，并掌握人员、车辆、无人机、药剂、设备等资源使用情况。该类用户的主要需求是明确任务对象、落实责任人员、跟踪处置进度和反馈辖区防控结果。
业务规则：巡查和处置任务应对应具体区域、点位或林班小班；任务应明确责任人、任务类型、完成时限和反馈要求；高风险区域、红色预警区域和历史高发区域应优先安排核查和处置；处置结果应与核查记录、现场照片、资源投入和复核意见关联保存。
功能指标：支持巡查任务、核查任务、处置任务的生成和状态跟踪；支持按辖区查看任务完成情况、处置进度和异常任务；支持人员、车辆、无人机、药剂和设备等资源记录；支持形成辖区处置台账和阶段性汇总材料。
预期结果：林场管理人员能够及时掌握辖区内病害线索、任务执行情况和处置结果，减少线下通知和人工汇总压力，提高基层防控组织效率。
1.4.1.3	一线护林员
功能模块名称：现场核查模块、移动巡护记录模块、处置反馈模块、异常线索上报模块
需求描述：一线护林员承担疑似点位现场核查、日常巡护和处置结果反馈工作，需要平台提供清晰的任务信息、点位位置、现场记录要求和反馈渠道。该类用户的主要需求是按任务到达现场，确认病害症状，记录疫木数量和现场情况，并将核查或处置结果及时上报。
业务规则：护林员接收的任务应包含点位位置、核查对象、任务说明和完成时限；现场记录应包括核查时间、位置、照片、病害症状、疫木数量和初步判断；对无法到达、点位不准确、病害不明显等情况应允许填写异常说明；现场核查结果应作为后续研判和处置的重要依据。
功能指标：支持核查任务接收、现场定位、照片记录、文字记录和结果提交；支持异常情况说明和补充上报；支持查看本人任务状态和历史核查记录；支持将现场核查结果关联到疑似病害点位或处置任务。
预期结果：提高一线核查记录的完整性和及时性，减少纸质记录和重复上报，保证监测结果能够落到具体现场。
1.4.1.4	无人机操作人员
功能模块名称：无人机巡查任务模块、航线记录模块、影像采集回传模块、重点区域精查模块
需求描述：无人机操作人员根据遥感筛查结果、历史高发区域或林场任务安排开展重点区域巡查，需要平台提供明确的巡查范围、任务要求和成果回传方式。该类用户的主要需求是完成疑似区域的精细化影像采集，为后续疫木识别和现场核查提供更高分辨率资料。
业务规则：无人机巡查任务应与疑似区域、预警区域或林场巡查计划对应；巡查成果应记录采集时间、巡查区域、航线信息和影像资料；受天气、空域、地形等影响无法完成任务时，应记录原因并反馈；无人机影像应进入统一监测资料库，供遥感工程师和森防站进一步使用。
功能指标：支持巡查任务查看、巡查范围确认、航线记录登记、影像资料上传和任务完成状态反馈；支持将无人机影像与疑似点位、核查任务或预警区域关联；支持输出重点区域巡查成果。
预期结果：提高重点区域精查效率，缩小地面核查范围，增强疑似病害点位定位精度。
1.4.1.5	森防站工作人员
功能模块名称：灾害研判模块、分级预警模块、任务派发模块、统计上报模块、闭环验收模块
需求描述：森防站工作人员负责病害监测成果汇总、灾害等级研判、预警信息形成和防控任务组织，需要平台把遥感、无人机、地面核查和历史疫情资料整合起来，形成可判断、可派发、可上报的业务成果。该类用户的主要需求是掌握区域灾情态势，组织分级预警和防控处置，并对处置结果进行复核。
业务规则：灾害研判应综合多源监测结果和现场核查结论；预警等级应与风险程度、空间范围和处置优先级对应；任务派发应明确责任单位、责任人和处置时限；处置完成后应进行复核或验收，未达标区域应进入二次处置流程；统计上报应保持区域、时间、等级和处置状态口径一致。
功能指标：支持多源监测成果汇总、灾害等级判别、风险区域表达、预警清单生成、任务派发、处置结果审核和统计报表输出；支持按行政区、林场、林班小班或预警等级查看灾害和处置情况。
预期结果：森防站能够形成从病害发现到预警处置的连续业务管理流程，提高灾害研判效率和防控任务组织能力。
1.4.2	周边业务人员用户需求
1.4.2.1	林业局
功能模块名称：区域态势总览模块、分级预警监管模块、防控成效评估模块、统计决策支持模块
需求描述：林业局作为管理决策主体，需要掌握区域内松材线虫病发生范围、风险等级、处置进度和防控成效。该类用户不直接承担一线核查任务，更关注平台能否提供清晰的态势信息、重点区域监管依据和阶段性统计成果。
业务规则：平台展示和统计口径应与行政区划、林业管理责任范围和防控周期一致；重大预警区域、跨区域扩散风险和处置滞后区域应能够被重点标识；对外上报和共享的数据应经过审核，避免未经确认的信息直接作为正式结论。
功能指标：支持区域灾情总览、风险分区查看、预警等级汇总、处置进度统计、防控成效对比和专题图输出；支持按行政区、时间、灾害等级和处置状态形成统计材料。
预期结果：林业局能够及时掌握区域防控总体情况，为防控部署、资源协调、考核评估和政策决策提供依据。
1.4.2.2	高校/科研人员
功能模块名称：样本数据分析模块、病害规律研究模块、模型效果评估模块、预警阈值优化模块
需求描述：高校和科研人员需要利用平台积累的遥感影像、样本数据、核查记录和处置结果开展病害传播规律、识别方法和防控效果研究。该类用户的主要需求是获取经过整理和授权的数据材料，并将研究结论反向服务平台模型优化和预警规则完善。
业务规则：科研使用的数据应符合授权范围和脱敏要求；样本数据应保留采集来源、核查结论、病害等级和时间信息；科研人员提出的模型或阈值优化建议应经过业务部门验证后再纳入平台应用；研究成果使用平台数据时应保留数据来源说明。
功能指标：支持样本数据查询、历史疫情资料导出、识别结果对比、模型效果统计和预警阈值分析；支持按时间、区域、病害等级和环境条件筛选研究数据。
预期结果：支撑科研人员开展病害识别、扩散规律和防控效果研究，提高平台监测预警方法的科学性。
1.4.2.3	自然资源保险公司
功能模块名称：灾害范围核验模块、损失评估辅助模块、处置证明查询模块、风险区域分析模块
需求描述：自然资源保险公司关注灾害发生范围、受损程度、处置记录和风险变化情况，需要平台提供相对客观的空间范围和业务记录，作为保险风险评估、理赔核验或灾后损失分析的参考依据。
业务规则：保险使用的灾害范围和损失材料应以审核后的监测结果、现场核查记录和处置记录为依据；涉及单位、个人或敏感空间信息时，应按照授权范围使用；保险评估结果不应替代林业主管部门的灾害认定结论。
功能指标：支持查看授权范围内的灾害区域、灾害等级、核查记录、处置状态和历史风险变化；支持生成灾害范围说明、处置记录摘要和风险区统计材料。
预期结果：提高保险评估资料获取效率，减少线下核验成本，为自然资源保险风险管理提供辅助依据。
1.4.3	运营维护人员用户需求
1.4.3.1	系统运维工程师
功能模块名称：基础架构监控、算法容器调度、性能预警系统
需求描述：负责监测预警平台的底层物理资源与应用层性能，包含服务器硬件、网络拓扑、以及识别算法容器的并发状态维护。需实时统计 CPU 负载、内存吞吐、磁盘 I/O 以及松材线虫识别算法在不同影像分辨率下的计算耗时。 业务规则： 监控系统需 7×24 小时运行；当系统触发资源阈值（如负载 > 85%）或业务处理异常（如单景影像识别 > 10分钟）时，必须通过短信/钉钉等多渠道向运维人员推送分级报警通知。 
功能指标：性能采样频率 ≤ 5秒/次，故障自动发现率 100%，系统日志滚动保留期 ≥ 180天。 
预期结果：运维工程师能通过全链路可视化看板掌握集群健康度，确保在春季枯死松树普查等高并发任务下，系统能自动扩容或排队而不崩溃。
1.4.3.2	用户管理员
功能模块名称：多级组织架构、RBAC 权限控制、用户全生命周期管理系统
需求描述：管理平台内跨部门、跨区域用户（林场员工、遥感工程师、第三方作业团队）的账号准入、身份认证及功能权限分配。 
业务规则：账号实行实名映射制，遵循“最小特权原则”；基层护林员仅开放移动端灾情上报权限，遥感工程师开放模型参数调优与 API 调用权限，实现数据与功能双重隔离。 
功能指标：账号新增/锁定响应时间 < 2秒，用户操作审计日志 100% 覆盖，支持基于模板的批量用户数据导入导出。 
预期结果：实现系统层面的安全隔离，确保不同层级人员“看不见、动不了”职权之外的敏感数据。
1.4.3.3	财务管理员
功能模块名称：监测项目成本核算、资源消耗计量、预算管控系统 
需求描述：统计并核算松材线虫监测全流程的精细化开支，包含原始卫星数据采购费、无人机飞服租赁费、以及计算算力成本（如 GPU 识别松材线虫模型产生的资源折旧与能耗资费）。 
业务规则：按月度/项目维度自动生成财务对账报表；当单月实际支出达到预算 90% 时，系统应自动识别并标记高能耗算法任务，触发预算超支预警。 
功能指标：算力费用统计误差 < 0.1%，费用统计精度需达到 0.01元，支持自定义周期的标准 Excel 报表一键导出。 
预期结果：实现监测平台运营成本的“账目化”管理，将模糊的运营开支转化为可审计的精准成本数据。
1.4.3.4	系统审计员
功能模块名称：关键决策溯源、敏感数据操作、安全合规审计系统 
需求描述：对系统内发生的重特大操作行为（如疫情预警发布、原始监测数据物理删除、系统阈值重置）进行独立的第三方审计与逻辑回溯。 
业务规则：审计日志采用加密存储与数字签名技术，确保包括管理员在内的任何人员均无权篡改或抹除已生成的审计流水。 
功能指标：关键业务审计覆盖率 100%；支持基于时间轴、用户指纹、操作指令等维度的毫秒级回溯查询。 
预期结果：确保每一笔疫情数据的发布与修改均有据可查，满足林业部门对灾害数据安全合规性的监管要求。
1.4.3.5	用户培训师
功能模块名称：灾害识别标准知识库、模拟实操、在线考核培训系统
需求描述：依托平台内置的教学模块，指导一线护林员识别感病松树特征，培训无人机操作员掌握标准化影像采集流程，并更新最新的系统操作手册。 
业务规则：建立权限联动机制，新入职用户必须完成指定的“松材线虫识别标准”课时并通过线上模拟考试后，系统才允许开通正式生产环境操作权限。 
功能指标：提供至少 20 种典型受灾阶段的样本知识库；支持在线题库随机组卷与系统自动阅卷评分。 
预期结果：提升一线人员业务素养，从源头确保采集上传的灾害样本质量，进而提高后端 AI 模型的识别准确率。
1.4.3.6	数据库管理员
功能模块名称：时空大数据存储优化、样本库同步、灾备管理模块
需求描述：管理松材线虫识别核心样本库，负责海量遥感影像、无人机倾斜摄影数据与地面监测矢量数据的存储优化、索引建立及跨库一致性维护。
业务规则：每日 0 点进行增量数据备份，每周一 0 点执行全量冷备份；必须确保地理空间实体数据（坐标信息）与其属性元数据在检索与更新时严格同步。 
功能指标：万级地理空间对象检索延迟 < 1s，数据恢复点目标（RPO） ≤ 24小时。 
预期结果：支撑平台在高频调用下依然能快速调取样本数据，保证林业时空数据的安全性与检索高效性。
